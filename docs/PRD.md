## 1. 背景与问题

小红书等平台流行「测一测」（如「你最像哪个历史人物」）类测验。常见卖法是私聊收款后发一个长期有效链接，**几乎无法防止转发、复用和倒卖**。

本产品做成多租户测验平台：

- **ToC**：卖的是「一次测试资格」（兑换码），不是永久裸链。
- **ToB**：卖的是后台使用权（时间 + 码数上限），租户可自行发电、站外售卖。
- **平台方（超管）**：开停租户、发放套餐额度，总控全局。

---

## 2. 目标与非目标

### 2.1 目标

1. C 端可完成：打开链接 → 输码 → 答题 → 出结果（核销）→ 导出结果。
2. 租户可完成：登录 → 查看额度 → 生成/作废兑换码 → 查看核销情况。
3. 超管可完成：登录 → 创建/启停租户 → 配置到期时间与码数上限。
4. 同一公开链接可传播；**无有效未用码则无法完成一次完整测试**。

### 2.2 非目标（MVP 明确不做）

- 站内支付 / 自动发卡
- 租户自定义题目、答案、结果映射
- 功能权限矩阵、角色可配置 ACL
- 多套测验、品牌装修、子域名白标
- 强制答题用户注册登录
- 设备指纹作为唯一防刷手段
- 内容审核流、数据报表大盘

## 3. 用户与商业模式

### 3.1 角色

| 角色 | 说明 |
| --- | --- |
| 答题用户（C） | 获得链接 + 兑换码后完成测验并查看/导出结果 |
| 租户管理员（B） | 购买后台使用权；站外收款后向 C 发放兑换码 |
| 平台超管 | 运营方；管理租户与套餐额度 |

### 3.2 收入线

| 线 | 卖什么 | MVP 履约方式 |
| --- | --- | --- |
| ToC | 一次测试资格 | 站外收款 → 人工/租户发兑换码 |
| ToB | 后台使用权 | 站外收款 → 超管在后台写入「到期时间 + 码数上限」 |

### 3.3 防复用与防转卖原则

- **商品是兑换码，链接只是入口门脸。**
- 公开活动链接可长期存在；无码或码无效则不能完成测验。
- 一码对应一次完整测试资格；**出结果时核销**。
- 超管停用租户或租户过期 → 其码不可再用于完成测验。

## 4. MVP 范围

### 4.1 产品一句话

**全站共用一套固定题库与结果映射；多租户只经营兑换码额度；超管只发放时间与码数上限。**

### 4.2 固定内容（不可配）

全站唯一一套「死」配置（代码或静态配置文件）：

- 题目列表
- 选项及计分/标签规则
- 结果映射表（得分区间或标签组合 → 结果文案/形象）

所有租户发出的码，答题内容完全相同。租户差异仅在：所属码、额度、是否在有效期内。

### 4.3 功能清单

#### C 端（功能页）

| 功能 | 说明 |
| --- | --- |
| 输码页 | 打开活动链接，输入兑换码 |
| 答题页 | 按固定题库作答 |
| 结果页 | 展示映射结果；支持导出（优先结果长图/分享图） |
| 错误态 | 码无效、已用、过期、占用超时、租户停用/过期等 |

#### 租户后台

| 功能 | 说明 |
| --- | --- |
| 登录 | 租户账号登录 |
| 概览 | 到期日、码数上限、已用/剩余 |
| 兑换码管理 | 生成（扣剩余额度）、列表、作废 |
| 核销记录 | 极简列表（何时核销、哪个码） |

#### 超管后台

| 功能 | 说明 |
| --- | --- |
| 登录 | 超管账号登录 |
| 租户列表 | 创建租户、启用/停用 |
| 租户额度 | 设置/修改到期时间、码数上限 |

### 4.4 兑换码状态机

```text
未用
  | 输码校验成功
  v
占用中  ----占用超时（如 24h）----> 回到未用（或作废，实现时二选一并写死）
  | 生成结果成功
  v
已用

任意未终态均可被：超管/租户作废、租户停用、活动/租户过期 → 不可再完成测验
```

**核销时机（已锁定）：出结果时核销。**  
输码成功仅进入「占用中」，允许中途退出后在同一会话内续答。

**安全约束：**

- 出结果接口必须校验「码 + 会话」绑定，禁止只靠前端跳转出报告。
- 生成码时扣减租户剩余额度；作废**未用**码时退回额度（MVP 建议做，降低误操作成本）。
- 「占用中」的码不作废退额（避免刷退）；超时回退规则实现时写死一种。

### 4.5 权限模型（MVP）

权限写死，无配置界面：

| 角色 | 固定能力 |
| --- | --- |
| C | 输码答题、看结果、导出 |
| 租户 | 管理本租户码与查看本租户记录 |
| 超管 | 管理全部租户与额度 |

### 4.6 页面与路由建议

| 路径建议 | 页面 |
| --- | --- |
| `/` 或 `/q/:slug` | C 端输码/答题入口 |
| `/admin/login` | 后台登录 |
| `/admin/...` | 登录后按角色进入超管台或租户台 |

## 5. MVP 用户流程

### 5.1 ToC

```text
用户站外付款
  -> 客服或租户在后台生成兑换码
  -> 向用户发送「活动链接 + 兑换码」
  -> 用户打开链接，输入兑换码（校验并占用）
  -> 答题
  -> 出结果（核销）
  -> 导出结果图
```

### 5.2 ToB

```text
租户站外付款购买后台使用权
  -> 超管创建账号，写入到期时间 + 码数上限
  -> 租户登录后台
  -> 按需生成兑换码（消耗额度）并发给自己的 C 端客户
  -> 超管可随时停用租户或调整额度
```

## 6. 后期规划（Post-MVP）

按优先级分期，不纳入当前开发承诺。

### 6.1 第二期：可运营性

- 租户可配置题目 / 选项 / 结果映射（每租户自有题库）
- 活动（Campaign）概念强化：多活动、短链、独立开关
- 结果导出增强（PDF 等）
- 兑换码批量导入导出、自定义前缀
- 占用超时、退额策略可配置
- 基础数据看板（今日核销、转化漏斗粗指标）

### 6.2 第三期：商业化加深

- 站内支付（ToC 购码、ToB 购套餐）
- 套餐产品化：按时间、按码数、组合包
- 可配置功能权限（模块开关：自定义题库、导出、子账号等）
- 多管理员 / 子账号
- 自动发码（支付成功回调）

### 6.3 第四期：增长与风控

- 品牌白标（Logo、域名、结果页皮肤）
- 内容审核 / 敏感词
- 风控：异常核销、撞码、频率限制
- 可选 C 端登录以保存历史报告
- 开放 API 供代理商系统对接

### 6.4 与 MVP 的扩展关系

MVP 数据按 `租户 → 兑换码 → 答题会话 → 结果` 建模，题库先全局唯一。  
后期将「全局死题库」替换为「租户/活动级题库」时，C 端流程与码核销机制可复用，避免推倒重来。

---

## 7. 验收标准（MVP）

1. 无码或码已用/过期/作废时，无法走到有效结果页。
2. 同一兑换码仅能成功出结果并核销一次。
3. 输码后未出结果前，同一会话可续答；出结果后码为已用。
4. 租户剩余码数为 0 时无法再生成新码；未用码作废后退回额度。
5. 租户过期或被停用后，其码无法再完成测验。
6. 超管可创建租户并设置到期时间与码数上限。
7. 全站题目与结果映射为同一套固定内容，后台无配置入口。
8. 结果页支持至少一种导出（长图/分享图）。

## 8. 开放问题 / 实现时再定

| 问题 | 备注 |
| --- | --- |
| 占用超时后回到「未用」还是「作废」 | 需选一种写死；倾向回「未用」便于真实用户闪退 |
| 活动 slug 是否每租户一条固定链 | MVP 可全站一条链 + 码区分租户，或每租户一条链 |
| 超管/租户登录方式 | 邮箱密码或手机号；MVP 任选一种 |
| 结果图导出技术方案 | 前端截图或服务端出图 |
| 仓库/对外品牌名 | 仓库暂为 `codequiz-`，品牌名可后定 |
